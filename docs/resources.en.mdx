# Resources

The server exposes the platform reference as MCP resources. The agent reads
them without a tool call. The text is English, the same language as
core.telegram.org/bots/serverless, so it can be checked against that page.

| URI | Content |
|---|---|
| `tgcloud://docs/project-structure` | `tgcloud/` layout, handlers, endpoints, lib, schema.js. Project imports are relative paths **with** `.js`. Mini App static hosting |
| `tgcloud://docs/cli` | CLI reference: commands, `--dry-run` / `--safe` / `--yes` / `--local`, upgrade, webhook |
| `tgcloud://docs/sdk-db` | `sdk/db`: column types (`text`, `integer`, `real`, `numeric`, `blob`, `boolean`, `json`) and modes, query builder, raw SQL, no foreign keys, drops via `.deprecated` |
| `tgcloud://docs/sdk-api` | `sdk/api`: full Bot API, `BotApiError`, `InputFile` |
| `tgcloud://docs/sdk-fetch` | `sdk/fetch`: HTTP client, body helpers, 32 MB cap |
| `tgcloud://docs/limits` | Documented limits, and the quotas that are not published |

Inside a scaffolded project, read `AGENTS.md` and `docs/tgcloud-sdk.md` first.
Those files match the CLI that created the project. The resources are the
fallback when you are not inside one.

Source of truth in the repo: `resources/docs/*.md`. `npm run docs:check`
checks that every file is registered, that the two skill copies match, and
that every English page has ru, zh, ar, de, and fr siblings.
