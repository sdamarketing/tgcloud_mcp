# Безопасность

## Деструктивные операции требуют `confirm: true`

- `reset` — откат рабочих файлов к облачному снапшоту
- `push` с `force: true` — перезапись облачного состояния
- `migrate` с `dry_run: false` — применение миграций (в т.ч. удаление данных через `.deprecated`)
- `webhook_sync` с `drop_pending: true` — отброс очереди апдейтов

Без `confirm: true` инструмент возвращает отказ с инструкцией: агент обязан
показать пользователю, что будет изменено, и получить явное согласие.

## Токены

- CLI access token (`app<id>:<secret>`) передаётся в CLI через stdin / env
  и **маскируется** во всех выводах инструментов (как и Bot API токен).
- Не храните токены в файлах проекта: `.tgcloud/` (куда CLI пишет креды)
  должен быть в `.gitignore` — скаффолд это уже делает.

## Сетевой доступ

Серверу нужен доступ к `cloud.telegram.org`. Если на машине Telegram
недоступен, направьте CLI-обёртку через прокси (`TGCLOUD_CLI` → скрипт с
`HTTPS_PROXY` и `NODE_USE_ENV_PROXY=1`).
