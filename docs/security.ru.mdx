# Безопасность

`tgcloud-mcp` — неофициальный community-сервер. Он не аффилирован с Telegram.
Официальный инструмент платформы — `@tgcloud/cli`. Этот сервер только
запускает CLI и возвращает его вывод. Цепочка поставки —
[SECURITY.md](https://github.com/sdamarketing/tgcloud_mcp/blob/main/SECURITY.md).

## Деструктивные операции требуют `confirm: true`

- `reset` — откат рабочих файлов модулей к облачному снапшоту
- `push` с `force: true` — перезапись облачного состояния
- `upgrade` с `dry_run: false` — перенос проекта до 0.2.0 в `tgcloud/`
- `migrate` с `dry_run: false` — применение миграций, включая дропы `.deprecated`, если `apply` равен `"yes"`
- `webhook_sync` с `drop_pending: true` — сброс очереди апдейтов

Без `confirm: true` инструмент отказывает и требует показать пользователю,
что именно изменится, и получить явное «да».

`deploy` собирает и делает push без `--force`. Подтверждение не спрашивает.
Базу он тоже не мигрирует.

## Токены

- CLI access token (`app<id>:<secret>`) уходит в CLI через stdin или
  `TGCLOUD_TOKEN` и **маскируется** во всех выводах, как и Bot API токен.
- Не храните токены в файлах проекта. `.tgcloud/`, куда CLI пишет креды,
  скаффолд уже добавляет в `.gitignore`.

## Сеть

Серверу нужен доступ к `cloud.telegram.org`. Если с машины Telegram недоступен,
направьте обёртку CLI через прокси
(`TGCLOUD_CLI` → скрипт с `HTTPS_PROXY` и `NODE_USE_ENV_PROXY=1`).

Сервер не отправляет токены никуда, кроме CLI, а CLI ходит на платформу.
Произвольный код, кроме запрошенной команды CLI, он не выполняет.
